## Implementation

Added KR_BANNED=1, SessionStatus values UNSPECIFIED=0 / TAKEOVER_PENDING=1 /
TAKEOVER_FAILED=2, SessionStatusMessage (state=1, retry_after_ms=2), and
ServerPacket.session_status=7. Existing fields and enum values retain their numbers.
C0/C1 Pulse schemas and exports have no diff against the base.

Committed regression goldens cover legacy welcome/assignment/supersession bytes, bare NATS and
wrapped WS pending/failure/ban, unspecified status, defaults, unknown binary enum values, and
old-reader tolerance of field 7. Normal scripts/test.sh now executes the generated-JS wire tests.
scripts/build-session-artifacts.ps1 supplies Windows reproduction and holds the shared mutex for
generation, compilation, tests and packing. Integration instructions are in session-takeover-integration.md.

## Gates and ownership

No protocol collision was found. Connector identified existing KR_NEW_SESSION use for same-session
socket replacement: that must become close-only transport replacement or receive a separately
approved wire reason, since logical supersession is terminal. This decision was communicated to
connector and Unity owners; no extra enum was silently added. Protocol contains no ban producers.

Consumer gate: audit bans, authoritative-only supersession, exact session subjects, replay and stale
operation fencing, client suppression before close, watchdog behavior, old-client compatibility,
and a real two-client LiveKit Cloud revocation scenario. The local archive is not a stable release.
Remote CI must consume an immutable reviewed commit/artifact, followed by approved stable
publication and coordinated pins. No push, publication, remote PR edit, or consumer re-pin occurred.
